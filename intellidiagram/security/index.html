Security Policy

How LH Buyer Technology LLC protects IntelliDiagram for Confluence Cloud, and how to report a suspected vulnerability.

Last updated: October 9, 2026Provider: LH Buyer Technology LLC
Report a vulnerability
Email security@lhbuyertech.us rather than using a public issue tracker. We aim to acknowledge reports within one business day.

Reporting a vulnerability

Please include:

  • A clear description of the issue and its impact.
  • Reproduction steps, a proof of concept, or a sample diagram source.
  • The Atlassian site URL and app version where you reproduced it.
  • Whether you are an Atlassian tenant administrator, a page author, or a third party.

We coordinate disclosure timelines with Atlassian's Marketplace security process and follow the Atlassian Marketplace Security Bug Fix Policy. Please allow a reasonable window to triage and patch before public disclosure.

Security architecture

  • Runs on Atlassian Forge. The App's backend runs in the Forge sandbox and its interface in Forge's isolated Custom UI frames.
  • No data store. The App uses no Forge storage and no external database. Diagram source is saved in the page as macro parameters; converted images are ordinary page attachments.
  • No data egress. The manifest declares no external fetch domains and no remote backends, so the platform blocks the App from contacting anything outside Atlassian. Rendering happens in the user's browser.
  • User-scoped access only. Every Confluence request is made as the signed-in user, so the App can never read or change something that user could not. The App never acts with its own elevated identity.
  • Least-privilege scopes. read:page:confluence, read:space:confluence, write:page:confluence, and write:confluence-file. The last is needed only to attach a converted image; Confluence offers no narrower scope for uploading an attachment.
  • Untrusted input is sanitized. Diagram source is treated as untrusted. Mermaid runs in its strict security mode with HTML labels disabled, Markdown is rendered with raw HTML disabled, and all rendered SVG and HTML passes through DOMPurify before it reaches the page.
  • Server-side validation. Before a converted image is attached, the backend re-checks the page identifier, the size, and that the file really is a PNG or a script-free SVG, regardless of what the browser sent.
  • No secrets. The App holds no API keys, tokens, or credentials, and never asks for Atlassian account credentials.
  • Supported runtime and dependencies. The backend runs on a current Node.js LTS runtime. Dependencies are audited before each release.

Content security policy

IntelliDiagram requests two content-security relaxations for its own sandboxed frames, both required by the bundled rendering libraries and neither granting any network access:

  • Inline styles. Mermaid expresses a diagram's colors and layout as styles inside the SVG it generates. Without this, every shape renders solid black.
  • WebAssembly compilation. Graphviz is bundled as a WebAssembly module, which browsers will only compile when script evaluation is permitted. The App itself does not call eval or build code from diagram source, and loads no script from outside its own bundle.

Out of scope

The following should be filed as normal support requests rather than security reports:

  • Feature requests or behavior changes.
  • Confluence platform issues unrelated to this App.
  • Diagram syntax that an upstream library does not support.
  • Performance or appearance questions.
